# Desktop app changelog

One entry per wave of the Mac app on the `desktop` branch. The web page's own changelog is `../CHANGELOG.md`.

## Wave A, 20 and 21 October 2026: the page as a Mac app (5035a3d, ee1e4f9, b1b1c3d, 4d539d9, eeda57b, 64a2914, 7405a87)

A Tauri 2.12.4 shell under `desktop/` opens `index.html` and its three covers, unchanged at this point, in a Mac window. The page is served from inside the app under its own content security policy, which the shell also sends as a header, so a blocked request is refused by both copies. An allowlist script copies the page and its covers into the app before every build. The window shows nothing but the app's own page: navigation away and new windows are refused. The release build is optimised for size and the app is about 3 MB.

Two kinds of end-to-end tests run the real app on this Mac: `e2e.mjs` drives a test build from inside the page (it works while the screen is locked) and `app.mjs` drives the release app with real key presses through macOS. A run waits until nobody is using the Mac, stops at the first touch, and puts the app's data, the clipboard and the Downloads folder back as they were. `npm test` also runs the jsdom tests of the app's branch of the engine and static checks of the shell's configuration. A dropped release profile (the app had grown to 9.9 MB) was found by the size check and restored in 4d539d9; a config check guards it. 7405a87 checks the window size against bounds, because a display asleep gave 980 x 744 instead of 1000 x 760.

## Wave B, 20 and 21 October 2026: saving into a folder (336c8e6, ed952df, 9a16c73)

A guarded branch in `index.html` lets the page use the app when the app is there: "Choose a folder on this computer" opens macOS's folder panel, Save writes `YYYY-MM-DD HH-MM-SS.txt` into the chosen folder with the web page's names and counter, and the intro's wording speaks of an app instead of a browser. In a browser the branch does nothing. The app keeps the chosen folder's path in its own data folder and gives the page only the folder's name; it writes each file with create-new semantics, so no file is ever overwritten, and waits for the disk before it reports success. The folder panel is macOS's own, through `rfd`; Tauri's dialog plugin was not used because it adds a script to every page.

## Wave C, 21 October 2026: app behaviour and packaging (ef3784c to ce9dfc1)

Closing the window and quitting go through the page's own Esc first: the window's close button, Cmd+W, the app's Quit item (Cmd+Q) and a quit from the Dock all run Esc, which saves an open vault and locks it, before the app ends through macOS's normal termination. The window's title follows the cover on screen, the menu bar is the app's own with nothing in it but standard items, a right click on the page shows no menu (text fields keep theirs), and the app asks WebKit to keep Apple's Writing Tools away from the page.

Fixes from the first QA round: Save without a folder now writes into Downloads through the app, which reports the name it used or the failure, so the page says "Could not save" when nothing was written instead of "Saved" (DM-202); the bundle is now sealed with an ad-hoc signature and the hardened runtime (DM-201); the copy step bundles exactly the covers `index.html` names; new checks read the built app itself (its files, signature and the four page files embedded in its binary) and guard the shell's configuration; the test harness puts everything back when it is interrupted; the app declares macOS 11 as its minimum. A network watch around a full run of the end-to-end tests saw no socket and no network flow from the app or its web view's networking process. `SIGNING.md` lists the steps for a Developer ID signature and notarization. The branch carries the web page's 1.3.4 (ce9dfc1).

## Wave D, 21 October 2026: release candidate (25a8f2a onward)

Fixes from the second QA round and the DISH audit:

- Quitting right after typing could leave the last keystrokes out of the vault copy (QA-C-01; 7 of 165 quits in QA's runs and ours). WebKit commits a localStorage write about half a second after it arrives, and the app could end first. The quit now waits for a storage request that follows the write to be answered (at most 0.4 s) and then 0.7 s for the commit, inside the app's 3 s safety timer, so a quit takes about a second (08299bc). In the Delivery Manager's trial, alternating this build with one that lacks the wait, a large last save was lost in 11 of 60 quits without the wait and in none of 60 with it; quits straight after typing a few words lost nothing in either build that day (150 each), so that trial alone does not show the fix.
- When the app cannot keep or forget a folder, the page now says "Could not use that folder" or "Could not stop using the folder" and changes nothing (QA-C-02, a8d072e), and the app forgets a folder on disk before it forgets it in memory, so a failed forget keeps it in both (DM-220, 39c0573). Before, a failed "Stop using the folder" left the page and the app disagreeing.
- The web page's 1.3.5 and 1.3.6 fixes are merged (e174d4f, 03e7d97).

Tests: the quit tests press the real Quit item in the menu bar through Accessibility and send the quit request the Dock sends, and each checks that the way out went through the page; a new suite (`test:release`) opens the sealed release app through LaunchServices and ends it by its Quit item and by a Dock quit request, under a network watch; the folder button is shown to open macOS's folder panel at the normal window level; WebKit reports Writing Tools as off for the page; eighteen other commands are refused; the adapter has its own jsdom tests; the config checks refuse renamed, git, path and patched crates and extra bundled files, and the bundle check reads the crates the app is built from; the network watch finds the app by its process name, watches every interface and checks every launch's networking process; each run prints its exit code. The real-key suite gains Cmd+W, a click on the close button and the vault round trip in the release app; it waits for an unlocked Mac.

## Wave F, 21 October 2026: more save formats

The web page's 1.3.7, 1.3.8 and 1.4.0 are merged (7ea5703), so the page's Open reads plain `.txt` and `.md` notes in the app as it does on the web (proven in the jsdom suite; choosing a file in the app's Open panel has not been run yet).
